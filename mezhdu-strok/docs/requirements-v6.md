# МЕЖДУ СТРОК — VISUAL + WRITING SYSTEM v6

## 0. Задача

Обновить текущий проект **«Между строк»**.

Не перестраивать продукт с нуля и не ломать уже работающую механику анализа.

Главная цель этой итерации:

**сделать результат одновременно умным, человечным и визуально узнаваемым.**

Продукт должен ощущаться не как AI-тест и не как красиво оформленный JSON, а как:

**персональное визуальное исследование культурных и жизненных выборов человека.**

Ключевой принцип:

**разрозненные вещи → найденная связь → человеческое объяснение → визуальная композиция.**

---

# 1. Что сохранить

Сохранить:

- Analyst → Critic;
- доказательства для каждого вывода;
- 2–4 сильных паттерна вместо обязательного количества;
- неожиданные пары;
- возможность раскрыть «Почему?»;
- ivory / carmine / black / restrained gold;
- serif + sans;
- editorial-направление;
- отсутствие психологических диагнозов и типологий.

---

# 2. Главное продуктовое правило

Продукт анализирует **выборы человека, а не личность человека**.

Он не должен сообщать:

- кто пользователь «на самом деле»;
- его психотип;
- архетип;
- скрытые качества;
- травмы;
- «истинную сущность»;
- психологический диагноз.

Нужный эффект:

> «Я сам никогда не ставил эти вещи рядом, но теперь вижу, почему между ними действительно есть связь».

Недостаточный эффект:

> «Ну да, наверное, это похоже на меня».

---

# 3. Одна вещь не имеет одного значения

Не назначать каждому объекту стандартную интерпретацию.

Один и тот же объект может выполнять совершенно разные функции.

Например, **бокс** может быть:

- интенсивной физической нагрузкой;
- способом выпустить напряжение;
- контролируемым выходом злости или агрессии;
- ритмом;
- техникой;
- дисциплиной;
- ощущением силы;
- соревнованием;
- взаимодействием с соперником.

Не использовать автоматически:

- ринг;
- соперника;
- чтение противника;
- ожидание открытия;
- победу.

Если пользователь занимается recreational boxing, нельзя без дополнительных оснований интерпретировать это как взаимодействие с соперником.

Если пользователь дал собственный контекст:

> `бокс — помогает выпустить накопившуюся энергию`

он имеет приоритет.

Если контекста нет — интерпретация должна подтверждаться другими выборами пользователя.

Если подтверждения нет — не использовать объект как сильное evidence.

---

# 4. INPUT

Основной input должен ощущаться скорее как разговор, чем как анкета.

Главный экран:

# Расскажи, что тебе нравится.

Под ним:

**Пиши всё, что приходит в голову. Книги, фильмы, музыка, хобби, города, вещи, бренды, еда, люди, работа — что угодно. Ничего объяснять не нужно.**

Дополнительно:

**Если у какой-то вещи для тебя есть свой особый смысл, можешь дописать пару слов через тире. Это необязательно.**

Пример:

> Fleabag, фильмы Хичкока, бег, красная помада, Айвазовский, классическая музыка вживую, Vivienne Westwood, Лондон, придумывать проекты с нуля, Abramović, бокс — помогает выпустить накопившуюся энергию…

---

# 5. Подсказки для input

Вместо девяти тяжёлых обязательных блоков использовать категории как prompts:

КИНО  
КНИГИ  
МУЗЫКА  
ХОББИ  
МЕСТА  
ВЕЩИ  
ЕДА  
ЛЮДИ  
РАБОТА  
ДРУГОЕ

Категории нужны только для того, чтобы помочь человеку вспомнить больше.

Например:

### Хобби
*Что тебе действительно нравится делать? Спорт тоже сюда.*

### Работа
*Какие задачи тебе нравится делать, даже если они сложные?*

### Вещи
*Одежда, бренды, цвета, предметы — всё, что ты регулярно выбираешь.*

Не спрашивать:

**«Почему тебе это нравится?»**

Главный принцип сохраняется:

**минимум самоанализа на входе → максимум неожиданного узнавания на выходе.**

---

# 6. Parser

Перед Analyst использовать Parser.

Parser превращает свободный текст в структурированный список.

Пример:

```json
{
  "item": "бокс",
  "area": "hobbies",
  "user_context": "помогает выпустить накопившуюся энергию"
}
```

Или:

```json
{
  "item": "Хичкок",
  "area": "films",
  "user_context": null
}
```

Parser:

- не анализирует человека;
- не придумывает значения;
- не делает выводы;
- только выделяет объект, категорию и явно данный контекст.

---

# 7. Общая AI-архитектура

Использовать четыре разных задачи:

```text
INPUT
↓
PARSER
↓
ANALYST
↓
CRITIC
↓
WRITER
↓
VISUAL BRIEF
↓
IMAGE / COLLAGE ASSETS
↓
FRONTEND COMPOSITION
```

Важно:

**понять → проверить → хорошо написать → визуально интерпретировать**

Это разные задачи.

Не пытаться делать всё одним prompt.

---

# 8. ANALYST

Analyst ищет:

- 8–12 потенциальных паттернов;
- 4–8 неожиданных пар;
- несколько кандидатов на главный инсайт.

Он работает технически и может использовать сухой аналитический язык внутри системы.

Пользователь этот текст не видит.

Для каждого объекта Analyst должен рассматривать несколько возможных функций, если объект многозначный.

---

# 9. Критерии сильной связи

Паттерн проходит дальше, если:

- подтверждается минимум 3 вещами;
- включает минимум 2 разные сферы;
- желательно проходит через 3+ сферы;
- не является жанровым сходством;
- объяснение зависит именно от конкретных объектов;
- связь можно объяснить через действие или механизм;
- она не основана на общих качествах личности.

Не считать выводом:

- свобода + контроль;
- классика + бунт;
- интеллект + эмоция;
- глубина;
- смелость;
- творчество;
- энергия;
- аутентичность.

Если используются подобные понятия, нужно объяснить:

**что именно происходит.**

---

# 10. CRITIC

Critic проверяет:

1. Есть ли реальные доказательства?
2. Есть ли разные сферы?
3. Почему именно эти вещи оказались вместе?
4. Что здесь действительно неожиданного?
5. Можно ли этот текст без изменений показать другому человеку?
6. Не приписано ли вещи значение, которого пользователь не давал?
7. Не является ли вывод просто красивой абстракцией?
8. Не повторяют ли пары уже существующие паттерны?
9. Не сделаны ли выводы из того, чего пользователь НЕ назвал?
10. Нет ли психологии, эзотерики или комплиментов ради комплиментов?

Если связь слабая — удалить.

Две хорошие связи лучше четырёх средних.

---

# 11. WRITER — отдельный AI-этап

После Critic результат передаётся отдельному Writer.

Writer **не проводит анализ заново**.

Он получает:

- утверждённый главный инсайт;
- evidence;
- паттерны;
- неожиданные связи;
- user_context.

Его задача — превратить доказанный анализ в человеческий текст.

---

# 12. VOICE WRITER

System instruction:

> Ты не аналитик и не психолог.
>
> Ты редактор умного современного культурного издания.
>
> Перед тобой уже проверенный анализ. Не придумывай новых связей и не меняй его смысл.
>
> Напиши результат так, чтобы человек почувствовал: кто-то действительно внимательно посмотрел на его выборы и заметил между ними что-то небанальное.
>
> Язык ясный, точный, взрослый и sophisticated.
>
> Sophisticated здесь означает не сложные слова, а точность мысли.
>
> Это разговор умных взрослых людей, а не психологический тест, коучинг, рекламный текст или AI-summary.

---

# 13. Главное правило Writing

**Не описывать пользователя.  
Объяснять найденную связь.**

Не:

> Ты человек, который любит выражать эмоции.

Лучше:

> Чувство здесь почти всегда ищет материальный выход. В боксе напряжение можно перевести в движение; Abramović делает тело носителем опыта; у Айвазовского стихия удерживается композицией.

---

# 14. Не проговаривать очевидное

Не писать:

> Ты любишь много разных вещей.

> Среди твоих интересов есть книги, фильмы и спорт.

> На первый взгляд Хичкок и Agent Provocateur кажутся совершенно разными.

> У тебя разнообразные интересы.

> В твоих предпочтениях можно заметить несколько тем.

Человек уже знает собственный список.

Текст должен начинаться с **новой информации**.

---

# 15. Запретить GPT-язык

Не использовать как автоматические конструкции:

- «в твоих выборах прослеживается»;
- «тебя снова и снова привлекает»;
- «самое интересное здесь»;
- «на первый взгляд»;
- «дело не столько в X, сколько в Y»;
- «это не просто X — это Y»;
- «это говорит о том»;
- «пространство для»;
- «давать себе разрешение»;
- «проявленность»;
- «аутентичность»;
- «глубина»;
- «твоя энергия»;
- «проживание» как универсальный термин;
- «внутреннее становится внешним» как готовый штамп;
- искусственные триады;
- риторические повторения;
- псевдофилософские заключения.

Эти конструкции разрешены только если конкретный контекст действительно требует их.

---

# 16. Не начинать каждый абзац с «ты»

Избегать ритма:

> Ты выбираешь…  
> Ты любишь…  
> Ты снова…  
> Ты…

Предпочитать:

> У Хичкока и Agent Provocateur…

> В боксе напряжение…

> Красная помада здесь работает…

> Интерес появляется…

Фокус — на связи, не на описании личности.

---

# 17. Конкретность

Каждый важный абзац должен содержать:

- минимум 2 конкретных объекта;
- конкретное действие или механизм;
- объяснение, почему они оказались рядом.

Если заменить объекты популярными случайными вещами и абзац продолжает работать — текст слишком общий.

---

# 18. Главный инсайт

Не summary всех результатов.

Это **самое сильное найденное наблюдение**.

Структура результата:

## HEADLINE
3–8 слов.

Пример:

**Сильному чувству находится форма**

или:

**Не оставлять это внутри**

или:

**Интерес начинается до раскрытия**

Headline должен быть мыслью, а не категорией.

---

## MAIN TEXT

60–110 слов.

Один живой абзац.

3–5 предложений.

Ориентировочная структура:

1. сразу содержательная мысль;
2. конкретный пример;
3. второй неожиданный пример;
4. объяснение связи;
5. при необходимости — короткий итог.

Не делать эту структуру механической.

---

# 19. Пример нужного языка

Не:

> В твоих выборах прослеживается паттерн трансформации внутренней энергии во внешнюю форму.

Не:

> Тебя привлекают сильные эмоции и способы их выражения.

Лучше:

> Чувство здесь почти всегда ищет материальный выход. В боксе напряжение можно перевести в движение; Abramović делает тело носителем опыта; у Айвазовского стихия удерживается композицией; красная помада превращает состояние в жест, который считывается раньше слов. Это не требует вывода про характер. Просто в очень разных вещах оказывается важен один момент: когда чувство перестаёт быть бесформенным и с ним уже можно что-то сделать.

---

# 20. Пример неожиданной пары

Не:

> Хичкок и Agent Provocateur объединены напряжением.

Лучше:

> Хичкок и Agent Provocateur работают с одним довольно точным удовольствием: показать достаточно, чтобы внимание уже зацепилось, но остановиться раньше полного раскрытия. Интерес живёт именно в оставшемся промежутке.

---

# 21. Pattern writing

Каждый паттерн:

### TITLE
2–7 слов.

Естественный человеческий язык.

Например:

**Не оставлять внутри**

**Сила, которую удерживает форма**

**Не показывать всё сразу**

**Тело как способ выхода**

Не использовать обязательные `X → Y`.

---

### DESCRIPTION

2–4 предложения.

Описание должно провести читателя через найденную связь.

Не:

> Этот паттерн показывает стремление к выражению эмоций.

Лучше:

> Fleabag, I Love Dick и Abramović работают с материалом, который обычно проще оставить личным: желанием, неловкостью, телом, болью. Интерес появляется именно тогда, когда это перестаёт быть только внутренним и получает форму, которую уже может увидеть другой.

---

# 22. Evidence writing

Evidence — максимально конкретный.

Не:

> Бокс связан с энергией.

Лучше:

> Если бокс здесь работает как способ физически выпустить накопившееся напряжение, смысл находится не в соревновании, а в возможности дать сильному состоянию конкретное действие.

Не:

> Айвазовский выражает сильные эмоции.

Лучше:

> У Айвазовского море может быть почти стихийным, но оно никогда не остаётся хаосом: свет, движение и композиция удерживают эту силу внутри картины.

---

# 23. Writer Quality Check

Перед возвращением текста Writer должен проверить:

### Test 1
Есть ли предложение, которое подойдёт почти любому?

→ удалить или конкретизировать.

### Test 2
Пересказывает ли текст список пользователя?

→ удалить.

### Test 3
Появилось ли психологическое заключение?

→ заменить наблюдением о самих выборах.

### Test 4
Есть ли характерный GPT-копирайтинг?

→ переписать проще.

### Test 5
Есть ли конкретные вещи пользователя?

→ если нет, текст недостаточно персональный.

### Test 6
Читается ли абзац как хороший текст из культурного журнала?

→ если нет, переписать.

### Test 7
Есть ли лишние слова?

→ сократить.

### Test 8
Объясняет ли текст действительно что-то новое?

→ если нет, не показывать.

# 24. VISUAL SYSTEM

Весь проект перестроить вокруг утверждённого visual reference:

**архитектурный editorial collage + исследовательская схема + fashion/art publication.**

Основное ощущение:

**персональное визуальное исследование.**

Не использовать эстетику:

- SaaS;
- dashboard;
- AI assistant;
- personality quiz;
- одинаковых rounded cards;
- network graph;
- стандартного mind map.

---

# 25. Визуальная формула

**точность чертежа + эмоциональность изображения**

Использовать:

- warm ivory paper;
- почти чёрный;
- deep carmine;
- muted antique gold;
- black-and-white / muted photography;
- тонкие architectural lines;
- circles;
- crop marks;
- coordinates;
- handwritten micro annotations;
- photographic fragments;
- translucent overlays;
- negative space.

# 30. Main Result

Главный экран строить вокруг композиции в стиле утверждённого референса.

Центральная мысль:

# Сильному чувству  
# находится *форма.*

`форма` — restrained gold.

Вокруг — 3–5 смысловых зон.

---

# 31. Главное правило hierarchy

На всех result screens:

## СМЫСЛ
крупно

### evidence / объект
мелко

Не наоборот.

Например:

## Тело как способ выхода

`бокс`

или:

## Сила, которую удерживает форма

`бег · Айвазовский · классическая музыка`

Человек пришёл увидеть смысл, а не ещё раз свой список.

---

# 32. Visual fragments

Каждая смысловая зона может содержать фотографический fragment.

Не использовать буквальную пиктографику.

Не:

🥊 бокс  
💄 помада  
🎬 кино

Не делать floating-object poster.

Изображение должно быть встроено в общую композицию.

Например:

### Тело как способ выхода
фрагмент руки / бинта / движения.

### Сила, которую удерживает форма
волна + structural grid.

### Состояние становится видимым
часть лица / красный след.

### Не показывать всё сразу
тень / curtain / cropped figure.

# 33. Graphic lines

Использовать:

- tangent circles;
- guide lines;
- crosshairs;
- crop marks;
- measurement-like marks;
- маленькие индексы;
- соединительные линии.

Они не должны выглядеть как настоящая инженерная документация.

Их смысл:

**мы исследуем связи.**

# 34. Red brush marks

Красный использовать физически:

- brush;
- lipstick mark;
- fabric;
- ink;
- paint fragment.

1–3 жеста на композицию.

Не превращать красный в UI color everywhere.

# 35. Gold

Использовать минимально:

- ключевое слово;
- одна линия;
- точка пересечения;
- один важный графический элемент.

Gold = **«вот здесь мы нашли связь».**

# 38. Share card

# 45. Итоговый критерий проекта

После результата пользователь должен почувствовать:

**«Это красиво».**

Но этого недостаточно.

Также:

**«Это действительно про мои конкретные выборы».**

И главное:

**«Я никогда не связывал эти вещи именно так».**

Если результат только красивый — недостаточно.

Если результат только умный — недостаточно.

Если результат звучит как ChatGPT — недостаточно.

Итоговый продукт должен соединять:

**точность анализа × человеческий язык × визуальную авторскую систему.**

# 46. Финальный character

**арт-журнал × исследовательский альбом × персональный cultural analysis**

Не luxury ради luxury.

Не сложность ради интеллектуальности.

Не генеративная картинка ради картинки.

Каждый элемент должен помогать основной идее:

**вещи, которые выглядели разрозненными, начинают складываться в осмысленную систему.**
